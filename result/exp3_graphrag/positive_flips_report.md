### 1. e4b / IPAS-109-TEC-075

- 題源：iPAS；子圖：nonempty；n_edges_kept=3
- 題幹：下列何者是解決跨站請求偽造(Cross-Site Request Forgery, CSRF)的 最佳方式?
- 選項：A. 加入 HttpOnly；B. 過濾特殊字元；C. 使用 HTTPS 連線；D. 使用圖形驗證碼
- 正解／base／RAG：D／A／D
- base 推理：evidence 為空，依資安專業知識，CSRF 的核心問題是攻擊者利用用戶已登入的 Session 狀態發送請求。雖然 HTTPS (C) 是基礎安全要求，但它無法阻止 CSRF 本身。過濾特殊字元 (B) 和圖形驗證碼 (D) 主要用於防止輸入驗證或機器人爬取，而非針對會話劫持的 CSRF 攻擊。最標準且被認為是解決 CSRF 的最佳機制之一是加入 Anti-CSRF Token（通常透過 Cookie 或 Header 傳遞），而 HttpOnly 屬性雖然主要用來保護 Session Cookie 不被 JavaScript 讀取，但在選項中，如果將其理解為與會話管理相關的防護措施，或者考慮到現代框架常結合使用 Token 機制，但在純粹比較這四個選項時，最直接且標準的解決方案是 Anti-CSRF Token。然而，由於選項 A 提供的只是 HttpOnly (用於保護 Cookie)，而非 Anti-CSRF Token 本身，我們需要重新評估： 1. CSRF 的最佳防禦機制是 **Anti-CSRF Token**。 2. 選項 (A) `HttpOnly` 是防止 X
- RAG 推理：evidence 顯示 'captcha' (圖形驗證碼) 可以減輕 CSRF 的風險。在選項中，(D) 使用圖形驗證碼對應於 evidence 中提及的機制，且相較於其他選項（如 HttpOnly 主要用於防止 XSS，過濾特殊字元和 HTTPS 雖然是基礎控制但非針對 CSRF 的最佳單一解決方案），使用專門的驗證碼機制被視為更直接或推薦的額外防禦層級來應對 CSRF 攻擊。

### 3. e4b / IPAS-111-MGT-025

- 題源：iPAS；子圖：nonempty；n_edges_kept=4
- 題幹：通用漏洞評分系統(Common Vulnerability Scoring System, CVSS)是 一個可衡量漏洞嚴重程度的公開標準。CVSSv3 以基本指標群(Base metric group)、暫時指標群(Temporal metric group)及環境指標群 (Environmental metric group)等 3 個群組來進行判斷。關於基本指 標群,下列何者「不」是其考量因素?
- 選項：A. 機密性衝擊(Confidentiality Impact)；B. 攻擊途徑(Attack Vector)；C. 攻擊複雜度(Attack Complexity)；D. 可靠性衝擊(Reliability Impact)
- 正解／base／RAG：D／A／D
- base 推理：evidence 為空，依資安專業知識，CVSSv3 的基本指標群 (Base Metrics) 主要包含攻擊向量 (AV)、攻擊複雜度 (AC)、所需權限 (PR)、攻擊類型 (Scope)，以及三個衝擊指標：機密性衝擊 (Confidentiality Impact, C)、完整性衝擊 (Integrity Impact, I) 和可用性衝擊 (Availability Impact, A)。題目選項中，(A) 機密性衝擊是存在的；然而，在標準的 CVSSv3 描述中，通常會將三個衝擊指標列為 C、I、A。若單純從「不」考量因素的角度判斷，所有選項 (B), (C), (D) 皆屬於基本指標群的一部分（攻擊途徑、攻擊複雜度、可靠性衝擊）。但根據標準 CVSSv3 的結構，三個衝擊指標是 C, I, A。題目列出的選項中，(A) 機密性衝擊 (Confidentiality Impact) 是存在的；(D) 可靠性衝擊 (Reliability Impact) 應指可用性衝擊 (Availability Impact)。在標準的 CVSSv3 基本指標群中，三個衝擊指標是 C, I,
- RAG 推理：evidence 僅確認 CVSSv3 有基本、暫時及環境三個群組，但未列出基本指標群的具體組成。依資安專業知識，CVSS v3.x 的基本指標群（Base Metrics）主要包含：攻击向量 (Attack Vector)、攻击复杂度 (Attack Complexity)、所需权限 (Privileges Required)、用户交互 (User Interaction)；而其影响指标包括：机密性冲击 (Confidentiality Impact)、完整性冲击 (Integrity Impact) 和可用性冲击 (Availability Impact)。題目選項中，(A) 機密性衝擊、(B) 攻擊途徑、(C) 攻擊複雜度均為基本指標群的考量因素。可靠性衝擊（Reliability Impact）在 CVSS v3.x 中已被整合到「可用性衝擊」（Availability Impact）中，因此選項 (D) 不屬於獨立的基本指標群考量因素。
- 子圖證據：cvss 3.1 --[has_a]--> 基本指標組 cvss --[has_a]--> 弱點計分 cvss 3.1 --[has_a]--> 環境指標組 cvss 3.1 --[has_a]--> 時間指標組
- 初判：關鍵事實補強（結構澄清）。子圖確認 CVSS 3.1 的三個指標群結構，幫助模型聚焦、減少 base 在 C/I/A 定義上的混亂。
